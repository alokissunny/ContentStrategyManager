- **Brand Kit colours win.** When BRAND STYLE has a `palette` (the studio's selected Brand Kit colour set), use exactly its three colours and no other hues (photos excepted): `primary` = all text and any dark surface, `background` = the slide ground, `accent` = the pointing colour only (a key word, kicker, rules, small marks — never body copy). With no palette, choose a restrained palette of your own, still written through the roles below.
- **Colour roles (required — the studio recolours slides through them).** Declare the colours ONCE, at the top of the `<style>` block: `:root { --brand-primary: …; --brand-background: …; --brand-accent: …; }` (with a palette: its `primary`, `background`, `accent` hex values). Every other colour in the CSS, inline styles and SVG `fill` / `stroke` is `var(--brand-primary)`, `var(--brand-background)`, `var(--brand-accent)` or a `color-mix()` of them — e.g. `color-mix(in srgb, var(--brand-primary) 70%, var(--brand-background))` for muted copy, `color-mix(in srgb, var(--brand-primary) 12%, var(--brand-background))` for a secondary ground. No hex, `rgb()`, `white` or `black` outside that `:root` rule. A dark slide is `background: var(--brand-primary); color: var(--brand-background);`.
- **Brand Kit fonts win.** In the same `:root` rule declare `--brand-font-heading`, `--brand-font-body` and `--brand-font-detail`, and use only those vars in `font-family` (heading = headline / quote / stat; detail = kicker / label / caption / index / CTA; body = the rest). When BRAND STYLE has `fonts`, put each entry's `stack` verbatim in the matching var and `<link>` every URL in `fonts.stylesheets` in `<head>`; an entry with no `stylesheet` is the studio's own font, which the app loads — name it, never link it. A role it leaves out is yours to choose (load that face). Size lines for the brand's actual families and use only the weights and italics they load.
